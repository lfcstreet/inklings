# Requirement 10C-FIX-01 — Fix to Requirement 10C
## Same-Line Sentence Visibility

### Purpose

This is a FIX to the previously implemented:

    Requirement 10C — Sentence-Based Visibility with Line-Based Outer Fade

The existing 10C behavior is mostly correct and should NOT be replaced.

The purpose of this fix is to correct one visual problem:

When the previous or succeeding sentence is visible at approximately 30%,
another sentence may partially share the SAME PHYSICAL DISPLAY LINE.

Currently, that other sentence becomes completely invisible.

This creates an unnatural-looking line where part of the text suddenly
disappears.

The fix is to allow that same-line text to remain visible at approximately
30%.

---

# 1. Existing 10C Behavior — KEEP UNCHANGED

The following behavior remains unchanged:

    Current sentence       → 100% visible

    Immediately previous
    sentence               → approximately 30% visible

    Immediately succeeding
    sentence               → approximately 30% visible

The current sentence remains fully visible.

The previous and succeeding sentences remain approximately 30% visible.

Do NOT change these values.

---

# 2. The Problem Being Fixed

Consider a physical display line containing:

    Sentence A. Sentence B. Sentence C.

Suppose:

    Sentence B = previous sentence
    Sentence C = current sentence

The desired behavior is:

    Sentence B → 30%
    Sentence C → 100%

But Sentence A may also occupy part of the same physical display line.

Sentence A should NOT suddenly become completely invisible while Sentence B
is visible on the same line.

That creates an undesirable visual discontinuity.

---

# 3. Same-Line Rule

If text from another sentence appears on the SAME PHYSICAL DISPLAY LINE as
the previous or succeeding sentence, that text may also remain visible at
approximately 30%.

This is intentional.

The rule is:

    Previous sentence → 30%
    Succeeding sentence → 30%

AND:

    Other sentence text sharing the same physical display line
    with either 30% sentence → approximately 30%

This is a visual leniency rule.

It is NOT a change to sentence detection.

---

# 4. Important — This Is Based on Physical Display Lines

The same-line rule is based on the actual rendered/wrapped lines on screen.

It is NOT based on:

- Character count
- Number of words
- Number of sentences
- Source-code lines
- Markdown lines

Use the actual visual/display line produced by the editor layout.

---

# 5. Example — Previous Sentence

Suppose the rendered text is:

    Sentence A. Sentence B starts here and continues onto
    another visual line. Sentence B ends here.

If Sentence B is the previous sentence:

    Sentence B → 30%

If part of Sentence A appears on the SAME physical display line as the
visible portion of Sentence B:

    Sentence A. Sentence B starts here and continues onto

then the portion of Sentence A on that same physical line may also be
approximately 30% visible.

Do NOT make that portion completely invisible.

---

# 6. Example — Succeeding Sentence

Likewise:

    Sentence C ends here. Sentence D starts here and continues
    onto another visual line.

If Sentence C is the current sentence and Sentence D is the succeeding
sentence:

    Sentence C → 100%
    Sentence D → 30%

If another sentence partially shares the same physical display line as
Sentence D, that portion should also remain approximately 30% visible.

---

# 7. Important Boundary

The same-line rule applies ONLY to text that physically shares a display
line with one of the two 30% sentences.

It does NOT make an entire neighboring sentence 30%.

For example:

    Sentence A continues on the line above.
    Sentence A. Sentence B starts here.

If Sentence B is the previous sentence:

    Sentence B → 30%

The portion of Sentence A sharing Sentence B's physical line:

    → approximately 30%

But Sentence A's continuation on the line above is NOT automatically 30%.

It is subject to the normal outer line-based fade.

---

# 8. Outer Fade — KEEP UNCHANGED

Everything outside the central visual region continues to use the existing
LINE-BASED outer fade from Requirement 10C.

The outer fade is NOT sentence-based.

Physical lines farther above and below the central region progressively fade
toward complete invisibility.

The existing behavior should remain:

    closer line → more visible
    farther line → less visible
    approximately 3 lines away → 0% / completely invisible

Do not replace this with sentence-based fading.

---

# 9. Combined Behavior

The final visibility model is therefore:

    Current sentence
        → 100%

    Previous sentence
        → 30%

    Succeeding sentence
        → 30%

    Other text sharing the same physical display line
    with either 30% sentence
        → approximately 30%

    Lines farther above/below the central region
        → existing progressive LINE-BASED fade

    Sufficiently distant lines
        → completely invisible

---

# 10. Priority Rules

When determining visibility, use the following conceptual priority:

### Priority 1 — Current sentence

If text belongs to the current sentence:

    100%

### Priority 2 — Previous / succeeding sentence

If text belongs to the immediately previous or succeeding sentence:

    approximately 30%

### Priority 3 — Same-line exception

If other text shares a physical display line with a previous/succeeding
sentence:

    approximately 30%

### Priority 4 — Outer line fade

All remaining text is handled by the existing physical-line outer fade.

This ordering is important.

---

# 11. Do Not Break Multi-Line Sentence Behavior

A sentence may span multiple physical display lines.

For example:

    This is one very long sentence which wraps across
    several physical display lines and continues here
    before finally reaching its period.

If this is the previous sentence:

    ALL of its physical lines → approximately 30%

The same-line exception must NOT cause different parts of that sentence to
receive different opacity.

The sentence-based rule remains authoritative for the previous/current/
succeeding sentences.

---

# 12. Scrolling

Do not change existing scrolling behavior.

Scrolling should continue to work exactly as before.

The existing scroll/browse behavior from Requirement 10C remains unchanged.

---

# 13. Cursor Movement

Do not change how the current sentence is determined.

When the cursor moves:

    New current sentence → 100%
    New previous sentence → 30%
    New succeeding sentence → 30%

Then apply the same-line exception and existing outer line fade.

---

# 14. Rotation

Do not change existing rotation behavior.

After rotation, the editor must recalculate the physical display lines because
text wrapping may have changed.

The same-line rule must therefore be based on the NEW rendered layout.

---

# 15. Typography

Do NOT change typography.

Keep:

    Courier Prime
    22sp

Do not modify:

- Font
- Font size
- Letter spacing
- Word spacing
- Line spacing
- Margins

This requirement is purely a correction to the 10C fade behavior.

---

# 16. Implementation Guidance

Do not rewrite the entire 10C implementation if it is already working.

Modify only the logic necessary to implement the same-line exception.

The implementation should conceptually determine:

1. Which sentence is current.
2. Which sentence is previous.
3. Which sentence is succeeding.
4. Which physical display lines contain those sentences.
5. Whether additional text from another sentence shares those physical lines.
6. Apply approximately 30% visibility to that same-line text.
7. Apply the existing line-based outer fade to everything else.

The exact implementation is up to the developer.

Do not introduce a new user-facing setting.

---

# 17. Required Source-Code Comment

Add a concise source-code comment explaining that this behavior is
intentional.

The comment should make clear that:

- Requirement 10C is primarily sentence-based for the central region.
- Text from another sentence sharing the same physical display line with a
  30% sentence is intentionally allowed to remain at approximately 30%.
- This prevents unnatural visual discontinuities.
- Text outside this region continues to use the line-based outer fade.

# Completion Criteria

This fix is complete when:

1. Current sentence remains 100% visible.
2. Previous sentence remains approximately 30% visible.
3. Succeeding sentence remains approximately 30% visible.
4. Other sentence text sharing the same physical display line with a 30%
   sentence is also approximately 30% visible.
5. That same-line exception does NOT make the entire other sentence 30%.
6. Text on other physical lines continues to use the existing line-based
   outer fade.
7. The outer fade still reaches complete invisibility at approximately the
   existing distance.
8. Multi-line sentences continue to behave as sentence-based units.
9. Scrolling remains unchanged.
10. Cursor movement remains unchanged.
11. Rotation correctly recalculates physical display lines.
12. Typography remains unchanged.
13. A source-code comment documents the intentional same-line exception.
14. No unrelated functionality is changed.
