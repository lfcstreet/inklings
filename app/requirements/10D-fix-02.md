# Requirement 10D-FIX-02 — Correct Sentence Capitalization for All Input Methods

## Purpose

This is a corrective FIX to:

- Requirement 10D
- Requirement 10D-FIX-01

The previous implementation attempted to manually handle capitalization for
all text input.

This caused inconsistent behavior, particularly with the Android on-screen
keyboard.

The capitalization responsibility must now be split appropriately:

1. Android's Input Method Editor (IME) should handle normal sentence
   capitalization for on-screen keyboard input.
2. The application should provide equivalent sentence capitalization for
   physical keyboard input, because a physical keyboard may not perform
   automatic sentence capitalization through the Android IME.

The goal is that the user gets consistent writing behavior regardless of
whether they use the physical keyboard or Android's on-screen keyboard.

---

# 1. Android On-Screen Keyboard — Use IME Sentence Capitalization

Configure the writing editor as normal sentence-based text input.

Use the appropriate Android / Jetpack Compose input configuration so that the
Android IME knows that this is a normal prose-writing field.

Conceptually this corresponds to:

    TYPE_CLASS_TEXT
    +
    TYPE_TEXT_FLAG_CAP_SENTENCES

Use the appropriate modern Compose API for the version already used by the
project.

Do NOT manually intercept and uppercase characters received from the
on-screen keyboard.

The Android IME should be allowed to perform normal sentence capitalization.

---

# 2. Physical Keyboard — Application-Side Capitalization

A physical keyboard may send characters directly without the IME applying
sentence capitalization.

Therefore the application must provide sentence capitalization for physical
keyboard input.

When text is entered through a physical keyboard, the application should
capitalize the first alphabetic character when it is appropriate to begin a
new sentence.

This should be implemented only inside this application's writing editor.

Do NOT implement any global keyboard hook.

---

# 3. Input Method Detection

The implementation should distinguish between:

- Text arriving through the Android IME / software keyboard.
- Key events arriving from a physical keyboard.

Do not assume that every text insertion is a physical keyboard event.

The purpose is to avoid double-processing characters coming from the
on-screen keyboard.

The Android IME should remain responsible for its own capitalization.

---

# 4. Do Not Double-Capitalize

The application must NOT blindly uppercase every first character that it
receives.

For on-screen keyboard input:

    Android IME
        ↓
    sentence capitalization
        ↓
    application accepts the text

The application should not then uppercase the same character again.

For physical keyboard input:

    Physical keyboard
        ↓
    application detects appropriate sentence position
        ↓
    application capitalizes the first alphabetic character

---

# 5. New Session

A NEW writing session begins with an empty document.

The first alphabetic character typed in the new session should normally be
uppercase.

### On-screen keyboard

Let the Android IME handle this through the sentence-capitalization
configuration.

### Physical keyboard

The application should capitalize the first alphabetic character.

Example:

    NEW

    User types:

    this is my first sentence

Expected:

    This is my first sentence

The user should not have to manually press Shift for normal prose entry.

---

# 6. First Character Only

Automatic capitalization must affect only the appropriate first alphabetic
character.

Example:

    this is a test

Expected:

    This is a test

NOT:

    This Is A Test

After the first alphabetic character has been entered, the initial
capitalization state is consumed.

---

# 7. Sentence Capitalization for Physical Keyboard

When using the physical keyboard, the application should recognize the
appropriate start of a sentence.

A sentence normally begins:

- At the beginning of a new session.
- After a sentence-ending period followed by whitespace.

The application may use the editor's existing text state to determine this.

Example:

    I went home. this morning

When `t` is entered using the physical keyboard, the application should
produce:

    I went home. This morning

Only the first alphabetic character should be automatically capitalized.

---

# 8. Do Not Capitalize Every Word

The physical-keyboard capitalization logic must NOT behave like title case.

Example:

    this is a test

must become:

    This is a test

NOT:

    This Is A Test

---

# 9. Double-Space → ". " Remains

The existing custom behavior remains unchanged:

    [space][space]

becomes:

    .[space]

For example:

    I went home[space][space]

becomes:

    I went home. |

where `|` represents the cursor.

This is an application-specific feature and must remain implemented by the
application.

---

# 10. Capitalization After Double-Space

After the application performs:

    [space][space]
        ↓
    .[space]

the next sentence should begin with an uppercase character.

### On-screen keyboard

Allow the Android IME to handle sentence capitalization.

### Physical keyboard

The application should capitalize the first alphabetic character.

Example:

    I went home[space][space]this morning

Expected:

    I went home. This morning

---

# 11. Manual ". " Must Not Automatically Trigger App Capitalization

The application should distinguish its own double-space transformation from
a manually typed period.

If the user manually types:

    First sentence. second

the application should NOT blindly transform the `s` into `S` merely because
the text happens to contain ". ".

For physical-keyboard capitalization, sentence detection should be based on
the intended sentence-start state and normal editor behavior rather than
continuously scanning for every occurrence of ". ".

Do not create aggressive capitalization that changes existing text
unexpectedly.

---

# 12. Android IME Must Remain in Control of Its Own Behavior

Do not:

- Modify Gboard settings.
- Modify Android keyboard settings.
- Detect Gboard by package name.
- Detect a specific keyboard application.
- Assume Gboard is installed.
- Implement global keyboard hooks.

The writing editor should simply provide the correct Android text-input
configuration.

The installed IME decides how it responds.

---

# 13. Browser / Other Applications

This application's capitalization logic must exist ONLY inside this
application.

It must have no effect on:

- Browser address bars.
- Browser search fields.
- Other Android applications.
- Other text editors.
- System-wide keyboard behavior.

For example, a browser address bar should continue to behave according to
the browser's own input configuration.

The application must not attempt to control the keyboard globally.

---

# 14. Physical Keyboard Key Handling

Physical-keyboard capitalization must not rely solely on detecting the
literal character `t`, `a`, `b`, etc.

It should use the editor's current text/cursor state to determine whether
the inserted character is the first alphabetic character of a sentence.

The implementation must also account for:

- Shift already being held.
- Characters that are already uppercase.
- Non-alphabetic characters.
- Backspace.
- Cursor movement.
- Editing existing text.

If the user has already typed an uppercase character manually, do not modify
it.

---

# 15. Backspace

The user must be able to edit automatically capitalized characters normally.

Example:

    First sentence. Second

The user presses Backspace and types:

    second

The application must not continuously force the character back to uppercase.

Automatic capitalization should occur as an insertion behavior, not as a
permanent constraint on the text.

---

# 16. Cursor Movement

Moving the cursor must not unexpectedly capitalize unrelated text.

If the user moves the cursor into an existing sentence and types:

    hello

the application must not automatically change it to:

    Hello

unless the insertion point genuinely represents the beginning of a sentence.

Do not use a simplistic rule such as:

    "Previous character is a space → capitalize."

That would incorrectly capitalize ordinary words.

---

# 17. Pasting

Do not manually capitalize pasted text.

For example, if the user pastes:

    this is pasted text

the application should not arbitrarily transform it into:

    This is pasted text

Pasted content should remain as supplied.

---

# 18. Non-Alphabetic Input

If the next character is not alphabetic:

- Do not attempt to uppercase it.
- Do not insert additional characters.
- Do not consume sentence-capitalization state unnecessarily.

Continue waiting for an appropriate alphabetic character where applicable.

---

# 19. Physical Keyboard and IME Must Share the Same Editor State

The application should maintain a coherent understanding of:

- Current cursor position.
- Current text.
- Whether the editor is empty.
- Whether the user is at the beginning of a sentence.

However, the actual capitalization mechanism differs:

    On-screen keyboard
        ↓
    Android IME capitalization

    Physical keyboard
        ↓
    Application-side capitalization

Both should produce equivalent normal prose behavior.

---

# 20. No Manual Capitalization for IME Text

Do not take text received through the normal Android IME pathway and then
run it through the physical-keyboard capitalization algorithm.

This could result in:

- Double capitalization.
- Unexpected text changes.
- Conflicts with the keyboard's own capitalization behavior.

IME-provided text should normally be accepted as provided.

---

# 21. Fade Behavior

Do NOT modify any fade behavior.

The following remain unchanged:

- Requirement 10C.
- Requirement 10C-FIX-01.
- Current sentence visibility.
- Previous/succeeding sentence visibility.
- Same-line exception.
- Line-based outer fade.
- Scroll behavior.

Sentence capitalization and sentence fading are separate systems.

Do not couple their implementations unnecessarily.

---

# 22. Typography

Do NOT change typography.

Keep:

    Font: Courier Prime
    Font size: 22sp

Do not modify:

- Letter spacing.
- Word spacing.
- Line spacing.
- Margins.

---

# 23. Save / New / Close

Do NOT modify:

- Save.
- New.
- Close.
- Auto-save.
- File naming.
- File locations.
- Writing-time tracking.
- Keyboard shortcuts.

Requirement 13 remains unchanged.

---

# 24. Remove Obsolete Capitalization Code

Inspect the existing implementation from:

- Requirement 10D.
- Requirement 10D-FIX-01.

Remove obsolete code that attempts to manually capitalize all input,
especially code that was introduced solely because the on-screen keyboard
was not behaving correctly.

Do NOT remove the physical-keyboard capitalization mechanism required by
this requirement.

The final architecture should be:

    ON-SCREEN KEYBOARD
        ↓
    Android IME sentence capitalization
        ↓
    Editor

    PHYSICAL KEYBOARD
        ↓
    Application sentence capitalization
        ↓
    Editor

    BOTH
        ↓
    Existing double-space → ". " behavior

---

# Completion Criteria

Requirement 10D-FIX-02 is complete when:

1. Android/Compose text input is configured for normal sentence
   capitalization.
2. The Android on-screen keyboard can perform sentence capitalization.
3. The application does not manually re-capitalize normal IME input.
4. Physical keyboard input receives equivalent sentence-capitalization
   behavior from the application.
5. New sessions begin with appropriate sentence capitalization.
6. Only the first alphabetic character of a sentence is affected.
7. Normal words are not converted to title case.
8. Double-space → ". " continues to work.
9. The character following the custom double-space transformation is
   appropriately capitalized for both input methods.
10. Manual editing is not continuously overridden.
11. Backspace works normally.
12. Cursor movement does not cause unexpected capitalization.
13. Pasted text is not arbitrarily capitalized.
14. No keyboard-specific implementation is introduced.
15. No global keyboard behavior is modified.
16. Browser and other applications are completely unaffected.
17. Fade behavior remains unchanged.
18. Typography remains unchanged.
19. Save/New/Close behavior remains unchanged.
20. Requirement 13 behavior remains unchanged.
21. Obsolete universal manual-capitalization code from 10D-FIX-01 has been
    removed.
22. No unrelated functionality is changed.
