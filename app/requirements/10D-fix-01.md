# Requirement 10D-FIX-01 — Fix 10D: Keyboard Input and New Session Capitalization

## Purpose

This is a FIX to Requirement 10D.

Requirement 10D introduced automatic capitalization after the existing
double-space → ". " behavior.

The current implementation works correctly with a physical keyboard, but
does not currently work correctly with the Android on-screen keyboard.

This fix must:

1. Make the existing 10D behavior work with BOTH physical and on-screen
   keyboards.
2. Make the first alphabetic character of every NEW writing session
   automatically uppercase.

The existing 10D behavior must otherwise remain unchanged.

---

# 1. Existing Double-Space Behavior

The application already converts two consecutive spaces:

    [space][space]

into:

    .[space]

For example:

    I went home[space][space]

becomes:

    I went home. |

where `|` represents the cursor.

This behavior must continue to work exactly as it does currently.

---

# 2. Capitalization After Double-Space

After the application automatically creates:

    .[space]

the next alphabetic character typed by the user must automatically be
capitalized.

Example:

    User types:

    I went home[space][space]this

Expected:

    I went home. This

The user must NOT need to press Shift.

---

# 3. Physical Keyboard

The existing physical-keyboard implementation already works.

Do NOT break or regress it.

Verify:

    Physical keyboard
        ↓
    double space
        ↓
    ". "
        ↓
    next alphabetic character
        ↓
    uppercase

Expected:

    I went home. This

---

# 4. Android On-Screen Keyboard

The same behavior MUST work when using the Android on-screen/software
keyboard.

For example, using the on-screen keyboard:

    I went home[space][space]this

must produce:

    I went home. This

The user must not need to manually press the Shift key.

---

# 5. Important Implementation Requirement

Do NOT implement the capitalization feature only through a
physical-keyboard-specific key-event mechanism.

Android's on-screen keyboard may deliver text through the normal Android
Input Method Editor (IME) / text-input pathway rather than through the same
hardware `KeyEvent` pathway.

The implementation must therefore correctly handle text inserted through
the Android software keyboard.

The behavior should be based on the actual text being inserted into the
editor, rather than assuming that every character arrives as a hardware
keyboard event.

Use the appropriate Jetpack Compose / Android text-input mechanism already
used by the editor.

---

# 6. Pending Capitalization State

When the application performs:

    [space][space]
        ↓
    .[space]

it should enter a pending-capitalization state.

The next alphabetic character inserted through either:

- Physical keyboard
- Android on-screen keyboard

must be capitalized.

After the first alphabetic character is entered:

    Pending capitalization → cleared

Subsequent characters must be entered normally.

---

# 7. Only the First Character

Automatic capitalization applies only to the first alphabetic character
after the automatically generated ". ".

Example:

    User types:

    I went home[space][space]this is good

Expected:

    I went home. This is good

NOT:

    I went home. This Is Good

Do not automatically capitalize every subsequent word.

---

# 8. Manual ". " Must Not Trigger It

The capitalization state must be associated specifically with the
double-space transformation.

If the user manually types:

    .[space]

the application must NOT automatically capitalize the next character merely
because it sees ". ".

For example:

    User manually types:

    First sentence. second

Do NOT automatically change it to:

    First sentence. Second

Only the existing double-space → ". " mechanism triggers the pending
capitalization state.

---

# 9. New Session — Initial Capitalization

When a NEW writing session is created, the application must initially expect
the first alphabetic character typed by the user to be uppercase.

For example:

    New session opened

The user types:

    this is my first sentence

The application must produce:

    This is my first sentence

The user must NOT need to press Shift.

---

# 10. New Session — First Character Only

The automatic capitalization applies only to the first alphabetic character
of the new session.

For example:

    User types:

    this is a test

Expected:

    This is a test

NOT:

    This Is A Test

After the first alphabetic character has been entered:

    Initial capitalization state → cleared

Normal typing resumes.

---

# 11. New Session — Empty Session

Creating a new session must NOT insert any text automatically.

If the user:

    Creates NEW session
    Does not type anything

then the document remains empty.

The capitalization state is simply waiting for the user's first alphabetic
character.

---

# 12. New Session — Both Keyboards

Initial capitalization must work with:

- Physical keyboard
- Android on-screen keyboard

Examples:

### Physical keyboard

    NEW
    ↓
    type "hello"

Result:

    Hello

### On-screen keyboard

    NEW
    ↓
    type "hello"

Result:

    Hello

---

# 13. Double-Space and New Session States

The application may have two situations in which capitalization is pending:

### A. New session

    New session
        ↓
    pending initial capitalization
        ↓
    first alphabetic character
        ↓
    uppercase
        ↓
    clear state

### B. Double-space

    [space][space]
        ↓
    ". "
        ↓
    pending sentence capitalization
        ↓
    next alphabetic character
        ↓
    uppercase
        ↓
    clear state

These states should be handled consistently.

---

# 14. Do Not Capitalize Unrelated Text

Automatic capitalization must NOT unexpectedly occur when:

- The user moves the cursor.
- The user scrolls.
- The user taps somewhere in the document.
- The user edits an existing sentence.
- The user pastes text.
- The user manually types ". ".
- The user inserts text into an existing sentence.
- The user returns to an existing part of the document.

The capitalization state must only apply to:

1. The first alphabetic character of a genuinely new/empty writing session.
2. The first alphabetic character after an automatically generated ". "
   resulting from double-space.

---

# 15. Cursor Movement

For a new session:

If the document is still empty and the user moves the cursor without entering
text, do not insert or alter any text.

The initial capitalization state should only be consumed when the first
alphabetic character is actually inserted.

For the double-space behavior:

If the user moves the cursor away from the position immediately following the
automatically generated ". ", the pending sentence-capitalization state
must not unexpectedly affect unrelated typing.

---

# 16. Backspace and Editing

The user must remain able to edit the automatically capitalized character
normally.

For example:

    First sentence. Second

The user can press Backspace and change it to:

    First sentence. second

The application must NOT continuously force the character back to uppercase.

Likewise, editing existing text must not unexpectedly trigger the
capitalization behavior.

---

# 17. Non-Alphabetic Characters

The capitalization should apply when the next inserted character is
alphabetic.

If a non-alphabetic character is inserted first, do not blindly uppercase
it.

Do not introduce unwanted punctuation or text.

The pending capitalization state should be handled sensibly until an
appropriate alphabetic character is entered.

---

# 18. Fade Behavior

Do NOT modify any fade behavior.

Requirements:

- 10C
- 10C-FIX-01

remain unchanged.

After a new sentence begins, the existing sentence-based fade behavior must
continue to work normally.

Do not combine capitalization logic with sentence-fade logic unnecessarily.

---

# 19. Typography

Do NOT change typography.

Keep:

    Font: Courier Prime
    Font size: 22sp

Do not modify:

- Font
- Font size
- Letter spacing
- Word spacing
- Line spacing
- Margins

This requirement is about text-input behavior only.

---

# 20. Save / New / Close

Do NOT change the existing behavior of:

- SAVE
- NEW
- CLOSE
- Auto-save
- File creation
- File naming
- File locations
- Writing-time tracking
- BAS logging
- Keyboard shortcuts

The NEW action should simply establish the initial capitalization state for
the newly created empty writing session.

# Completion Criteria

Requirement 10D-FIX-01 is complete when:

1. Double-space → ". " continues to work.
2. The next alphabetic character after an automatically generated ". " is
   capitalized.
3. This works with the physical keyboard.
4. This works with the Android on-screen keyboard.
5. Only the first alphabetic character is affected.
6. Subsequent typing behaves normally.
7. Manually typed ". " does not trigger capitalization.
8. A NEW writing session starts with pending initial capitalization.
9. The first alphabetic character of a NEW session is automatically
   capitalized.
10. Initial capitalization works with the physical keyboard.
11. Initial capitalization works with the Android on-screen keyboard.
12. An empty new session remains completely empty until the user types.
13. Cursor movement does not cause unexpected capitalization.
14. Editing/backspace does not cause continuous forced capitalization.
15. Existing fade behavior remains unchanged.
16. Existing typography remains unchanged.
17. Existing SAVE/NEW/CLOSE behavior remains unchanged.
18. No unrelated functionality is changed.
